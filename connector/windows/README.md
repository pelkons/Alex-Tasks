# Alex Link (Windows)

Tray app that connects Outlook on a Windows computer to an Alex Tasks server.

- Mail and calendar go to the server every 10 minutes, or right away with "סנכרן עכשיו". Outlook is only read.
- Every 60 s it checks the outbox and sends approved replies through Outlook.
- A heartbeat goes out every 5 minutes.
- Tray icon colour: green = OK; yellow = Outlook closed or paused; blue = standby (another computer does the work); red = server rejected the token or has not answered for 30+ min; grey = not connected.

## One active computer

Only one connected computer works at a time. The server gives each one a role, `active` or `standby`:

- in the answer to pairing (`POST /ingest/pair`), with `active_device` (`name`, `last_contact_at`);
- in the answer to every heartbeat;
- after `POST /ingest/activate` ("העבר לכאן" in the tray menu), which makes this computer the active one.

In standby the app does not read Outlook, does not check the outbox and does not push mail. It only sends the heartbeat and checks for updates. The icon is blue and the status reads "במצב המתנה — פעיל ב-<name>".

If pairing returns standby, the app asks whether to move the work to this computer.

When the role changes, the app shows one notification:

- When the computer goes to standby, the app stops at the next safe point and never in the middle of a send.
- When it becomes active, it starts right away from where the server says (`/ingest/status`).

A server that sends no role is treated as `active`.

## Install

Run `AlexLink-Setup-<version>.exe`. No admin rights are needed.

- It installs per user into `%LOCALAPPDATA%\Programs\AlexLink`.
- It starts with Windows (`HKCU\...\Run`, value `AlexLink`). You can turn this off in the installer.
- Remove it from Settings → Apps.

Connecting:

1. On the site, open Settings → "מחשב Outlook" → "חבר מחשב חדש".
2. Copy the code (`alex://<host>:8130/XXXX-XXXX`) and paste it into the app's window.

## Files

| What | Where |
|---|---|
| Settings | `%APPDATA%\AlexLink\config.json` |
| Token and signing key | `%APPDATA%\AlexLink\secret.bin`, encrypted with DPAPI for the current Windows user |
| Pause | `PAUSE` (everything), `PAUSE_INGEST`, `PAUSE_SEND` in `%APPDATA%\AlexLink` |
| Logs | `%LOCALAPPDATA%\AlexLink\logs\connector.log` |
| Sync state, downloaded updates | `%LOCALAPPDATA%\AlexLink\data`, `...\updates` |

To move the sync state of the old script connector into the app (existing files are kept as `.bak`):

```
AlexLink.exe --import-state <old data folder>
```

## Updates

Once a day the app asks `GET /ingest/connector/latest` for `{version, download, sha256, size, signature}`.

It installs a newer version only when all of these hold:

- the download comes from the paired server itself;
- sha256 and size match;
- `signature` is a valid Ed25519 signature, made with the offline update key, over `alexlink-update-v1|<version>|<sha256>`.

The public key is in `src/alexconn/version.py`. The private key never goes to the server or into the repository. Without a valid signature, an update is ignored.

## Build

Needs Python 3.13 with `pywin32`, `requests`, `pyinstaller`, and Inno Setup 6.

```
.\build.ps1                       # tests, PyInstaller onedir, Inno Setup -> build\out
.\build.ps1 -SignKey <keyfile>    # also writes AlexLink-Setup-<version>.exe.sig
python -m unittest discover -s tests
```

Other tools:

- Signing keys: `tools\update_signing.py`.
- Icons are generated by `icons\make_icons.py` (needs Pillow).
